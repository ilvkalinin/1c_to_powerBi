# Playbook: жизненный цикл отчёта

Перед новым отчётом прочитай `source_objects.md`, `data_products.md` и
`business_rules.md`. Для существующего отчёта сначала разбери полный SQL, M,
DAX и model relationships. Зафиксируй потребителя, решения, grain строки и
времени, единицы, метрики, срезы, фильтры, исключения, историю, SLA и controls.

В mapping сначала выполни reuse review в порядке `REUSE → EXTEND → NEW`.
Одинаковое имя Power Query не доказывает общий физический источник. Каждое поле
имеет lineage, формула — описание, связь — доказательство; не переносить raw
данные без подтверждённого потребителя.

Однозначное правило из SQL/M/DAX/описания — `CONFIRMED`: не запрашивать его
повторно. Бизнес-, grain-, cohort-, formula-, relationship- и attribution-
выборы нельзя скрывать под `UNKNOWN` или `VALIDATION_PENDING`. Последний
допустим только для физического факта, проверяемого на сервере.

Полная нормативная версия: `full_policy_reference_2026-08-11.md`, разделы
«Требования перед новым отчётом», «Анализ зафиксированных правил» и audit.
