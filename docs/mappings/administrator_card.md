# Source-to-target mapping: карта администратора

Статус: `BUSINESS MAPPING CONFIRMED / TECHNICAL VERIFICATION PENDING`.

Mapping описывает одну логическую итоговую таблицу из Gymmy и внешнего журнала администраторов. Физический объект и SQL не выбираются.

## Гранулярность

Одна строка:

> дата × клуб × направление × источник × причина.

`Причина` применима только к источнику `Журнал администратора`.

Логический ключ:

> `(event_date, club_id, direction, source_type, reason_key)`.

## Источник Gymmy

| Правило | Текущая реализация | Целевой статус |
|---|---|---|
| карты | 12 кодов `Reference141X1.Code` | CONFIRMED полный текущий список; новый клуб добавляется вручную |
| события | два GUID `Fld5840` | CONFIRMED current |
| направление | `b2fad... = Выход`, `b414fb... = Вход` | CONFIRMED current |
| успешность | текущий запрос не фильтрует | CONFIRMED target: исключать `Fld5841 = 0` |
| клуб | последнее слово `Reference141X1.Description` | current / заменить подтверждённым соответствием |
| период | жёстко от 2025-01-01 | заменить общей политикой истории |

До агрегации кандидат ключа события:

> `(Period, Fld5837 Terminal, Fld5838 Client, Fld5839 EventID)`.

## Источник Excel

Подтверждён бизнес-смысл полей `дата`, `клуб`, `направление`, `причина`. Физические имена, типы, правила объединения файлов и очистки значений имеют статус `UNKNOWN` до получения примера файла либо M-кода.

## Power BI

Имя таблицы: `Использования карты администратора`.

Меры:

- `Входы администраторов`;
- `Входы Gymmy`;
- `Разница входов = Входы администраторов − Входы Gymmy`;
- `Выходы администраторов`;
- `Выходы Gymmy`;
- `Разница выходов = Выходы администраторов − Выходы Gymmy`.

Все базовые количества аддитивны по дате, клубу, направлению и причине. Разницы рассчитываются в DAX. Условное форматирование остаётся в Power BI.

## Не переносить

- ФИО/наименование карты после определения клуба;
- код карты в пользовательскую модель;
- терминал;
- исходный идентификатор события;
- GUID вида события;
- `Успех`: используется только для исключения нулевого значения и после отбора
  не переносится; `Сообщение` не переносится;
- сырые события на VM-2;
- отдельные факты входов и выходов.
