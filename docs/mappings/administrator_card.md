# Source-to-target mapping: карта администратора

Статус: `IMPLEMENTED / INITIAL BR-003 LOAD VALIDATED — AC-REC-001—002 / ARCHITECTURE — ADR-0023 / STAGE_2 GYMMY SOURCE CONTROLS CLOSED — SV-002, SV-100, AC-V05`.

Mapping описывает одну семантическую таблицу Power BI из
`mart.administrator_card_gymmy_daily` и внешнего журнала администраторов.
PostgreSQL реализует только Gymmy-часть этой таблицы; внешний журнал остаётся
за границей PostgreSQL.

SV-002 подтвердил наличие `public._inforg5836`; SV-100 — его physical event
key, boolean success и bounded наличие карт/направлений. AC-V05 подтвердил,
что все 12 согласованных карт однозначно сопоставляются каноническому клубу
через текущую текстовую метку. SV-100 также подтвердил source-side дневной
`COUNT(*)`; сверка с фактическими цифрами Power BI откладывается до post-load
приёмки и не является source-side blocker.

## Гранулярность

Одна строка:

> дата × клуб × направление × источник × причина.

`Причина` применима только к источнику `Журнал администратора`.

Логический ключ:

> `(event_date, club_id, direction, source_type, reason_key)`.

## Целевые поля

| Целевая колонка | Бизнес-описание | Источник / преобразование | Тип PostgreSQL | NULL | Статус / доказательство | Проверка |
|---|---|---|---|---|---|---|
| `event_date` | календарная дата использования | Gymmy `InfoRg5836.Period::date`; Excel — колонка даты | `date` | нет | CONFIRMED need | диапазон и timezone |
| `club_id` | стабильный клуб | Gymmy: 12 согласованных кодов карт → метка последнего слова текущего описания → `Reference132.ID`; Excel: колонка клуба → общий справочник | UNKNOWN | нет | VALIDATED current physical mapping — AC-V05 | при изменении списка карт повторить контроль |
| `direction` | вход или выход | Gymmy: два GUID `Fld5840`; Excel: колонка направления | `smallint`/`text` | нет | CONFIRMED current | допустимые значения |
| `source_type` | `Gymmy` или `Журнал администратора` | константа источника | `smallint`/`text` | нет | CONFIRMED BY DESIGN | два значения |
| `reason_key` | причина использования | Excel: нормализованная причина; Gymmy: техническое значение `Без причины` | UNKNOWN | нет | CONFIRMED need / external source pending | дубли написания |
| `reason_name` | русское название причины | Excel; у Gymmy `NULL` в пользовательском поле | `text` | да | CONFIRMED need | пустые и варианты |
| `usage_count` | число успешных исходных строк | `COUNT(*)` внутри целевой группы Gymmy `Fld5841 IS NOT FALSE`; для Excel — число строк журнала | `bigint` | нет | CONFIRMED — user decision / boolean validated SV-100 | сумма до/после агрегации |

## Источник Gymmy

| Правило | Текущая реализация | Целевой статус |
|---|---|---|
| карты | 12 кодов `Reference141X1.Code` | CONFIRMED полный текущий список; новый клуб добавляется вручную |
| события | два GUID `Fld5840` | CONFIRMED current |
| направление | `b2fad... = Выход`, `b414fb... = Вход` | CONFIRMED current |
| успешность | текущий запрос не фильтрует | CONFIRMED target: boolean `Fld5841 IS NOT FALSE` |
| клуб | последнее слово `Reference141X1.Description` | VALIDATED: для 12 текущих карт однозначно соответствует `Reference132.ID` |
| период | жёстко от 2025-01-01 | заменить общей политикой истории |

До агрегации кандидат ключа события:

> `(Period, Fld5837 Terminal, Fld5838 Client, Fld5839 EventID)`.

## Источник Excel

Подтверждён бизнес-смысл полей `дата`, `клуб`, `направление`, `причина`. Физические имена, типы, правила объединения файлов и очистки значений имеют статус `UNKNOWN` до получения примера файла либо M-кода.

## Power BI

Имя таблицы: `Использования карты администратора`.

Меры:

- `Входы администраторов`;
- `Входы Gymmy`;
- `Разница входов = Входы администраторов − Входы Gymmy`;
- `Выходы администраторов`;
- `Выходы Gymmy`;
- `Разница выходов = Выходы администраторов − Выходы Gymmy`.

Все базовые количества аддитивны по дате, клубу, направлению и причине. Разницы рассчитываются в DAX. Условное форматирование остаётся в Power BI.

## Не переносить

- ФИО/наименование карты после определения клуба;
- код карты в пользовательскую модель;
- терминал;
- исходный идентификатор события;
- GUID вида события;
- `Успех`: используется только для исключения нулевого значения и после отбора
  не переносится; `Сообщение` не переносится;
- сырые события на VM-2;
- отдельные факты входов и выходов.
