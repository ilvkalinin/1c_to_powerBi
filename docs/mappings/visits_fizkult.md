# Source-to-target mapping: «Посещения Физкульт»

Статус: `BUSINESS MAPPING COMPLETE / TECHNICAL VALIDATION DEFERRED`. Общее посещение, ДПФУ и купоны сохраняют `DISTINCTCOUNT` клиента по произвольному диапазону; ИП считает строки. SQL не создаётся.

Предлагаемый общий физический объект: `mart.visit_client_day`; архитектура — `docs/adr/0003-shared-visits-domain.md`. Отдельная таблица отчёта Физкульт не создаётся.

Подтверждённая минимальная гранулярность для показателей с `DISTINCTCOUNT`:

> дата посещения × клуб фактического посещения × стабильный обезличенный клиент.

Клуб определяется по фактическому месту входа/оказания услуги. Основной клуб доступа клиента не участвует в атрибуции и не должен исключать строку. Клиент Пушкинского, посетивший клуб Физкульт, учитывается.

Для общего посещения одной строки `дата × клуб` недостаточно. Нужен компактный классифицированный client-day набор с флагами категорий, без ФИО, абонементов и сырых услуг. Все повторные сырые входы одного клиента внутри этого ключа схлопываются.

ГП имеет другую исходную гранулярность: `дата × клуб` с готовой суммой `КоличествоПосетивших`, без идентификаторов клиентов. Смешивать её с client-day строками нельзя. Используется общий маленький объект `mart.club_day_metrics`, куда также входят только подтверждённые показатели той же гранулярности.

## Дневной набор ГП

Гранулярность:

> дата события × клуб группового занятия.

| Целевая колонка | Бизнес-описание | Источник / преобразование | PostgreSQL тип | NULL | Статус | Проверка перед SQL |
|---|---|---|---|---|---|---|
| `event_date` | дата группового занятия | `Document279.Fld3218::date` | `date` | нет | CONFIRMED | timezone и границы дня |
| `club_id` | клуб занятия | `Document279.Fld3224` | UNKNOWN | нет | CONFIRMED | FK клуба |
| `group_program_visit_count` | сумма посетивших ГП | `SUM(InfoRg8675.Fld8677)` | `integer`/`bigint` | нет | CONFIRMED | проведение/удаление и один state на занятие |

`with_trainer_count`, `without_trainer_count` и проценты физически не хранятся:

- `С тренером = ГП + купон + ДПФУ + ИП`;
- `Без тренера = всего - с тренером`;
- доля = категория / всего.

Категории являются отдельными показателями, но не обязаны быть взаимоисключающими. Одно фактическое событие может попасть в несколько показателей; бизнес-формула всё равно складывает их без дедупликации между категориями. Поэтому `С тренером` теоретически может превышать `Посещения всего`, а `Без тренера` — стать отрицательным; это принятое следствие текущего бизнес-правила, а не техническая ошибка витрины.

### Показатель ИП

После получения отчёта «Отчет по ИП» хранение `ip_training_count` в client-day наборе приостановлено. Те же строки нужны с детализацией сотрудника и услуги, поэтому предполагается считать `Посещения ИП` из одного общего факта тренировок ИП: `docs/mappings/ip_training.md`.

До подтверждения ключа и состояний этот факт не утверждён, но дублирующее поле в `mart.visit_client_day` также не должно реализовываться.

## Временный source-side ключ

Для классификации понадобится стабильный идентификатор исходного события. Кандидаты:

- регистратор + номер строки регистра посещений;
- ссылка документа посещения;
- ссылка занятия/предварительной записи + клиент + услуга.

Статус: `UNKNOWN`. Выбор по совпадению названий запрещён; нужны metadata-кардинальность и контрольные строки.

Для точного текущего DAX требуется сохранить стабильный обезличенный ключ клиента до Power BI. Исходный ID, код клиента и ФИО переносить не требуется.

## Подтверждённая классификация ДПФУ

Текущий запрос:

- связывает движения `AccumRg7575` с датой занятия из проведённых `Document279` и `Document329`;
- берёт фактический клуб из `AccumRg7575.Fld7577`;
- оставляет номенклатуру с видом `Услуга`;
- исключает направления `Членство` и `Прочие членство`;
- исключает услугу `посещение клуба`;
- оставляет перечисленные фитнес-направления;
- исключает тип оплаты `Купон`;
- исключает клиентов с признаком `Сотрудник`;
- после Power Query группирует по дате, клиенту и клубу;
- DAX считает `DISTINCTCOUNT(КодКлиента)`.

Фильтр по `ОсновнойКлубДоступа` из текущего Power Query должен быть удалён согласно подтверждённому правилу фактического клуба. Вместо исключений `Пушкинский` применяется включающий перечень 12 клубов Физкульт.
