# Data contract: «KPI Фитнеса»

Статус: `DESIGNED COMPOSITE MODEL / IMPLEMENTATION DEFERRED / TECHNICAL VALIDATION REQUIRED`.

Отдельный KPI-факт не создаётся (ADR-0012). Модель Power BI использует общие
факты с разными grain.

## Факты и минимальные поля

| Таблица Power BI | Объект | Grain | Поля Power BI |
|---|---|---|---|
| `Оказанные услуги ДПФУ` | `mart.ancillary_revenue_movement` / контрактное представление | движение услуги | `Дата`, `ID клуба`, `Клуб`, `Ключ клиента`, `Код клиента`, `ID сотрудника`, `Сотрудник`, `ID услуги`, `Услуга`, `ID вида деятельности`, `Вид деятельности`, `Формат тренировки`, `Категория расчёта`, `Возрастная категория`, `Количество`, `Выручка` |
| `Тренировки ИП` | `mart.ip_training_daily` | дата × клуб × сотрудник × клиент × услуга | контракт `ip_training` |
| `План ДПФУ` | `mart.dpfu_plan_assignment` | дата × клуб × направление × тренер × плановый клиент | `Дата`, `ID клуба`, `ID вида деятельности`, `ID сотрудника`, `Ключ планового клиента`, `Код планового клиента`, `Плановая выручка` |
| `Выручка ИП` | `mart.ip_revenue_daily` | дата оплаты × клуб × услуга | `Дата оплаты`, `ID клуба`, `ID услуги`, `Выручка ИП` |
| `Клиентская база по дням` | `mart.client_base_daily` | договорный daily-grain | поля существующего продукта |

Идентификаторы в целевых объектах — `text`; даты — `date`; суммы/количества —
`numeric`; флаги — `boolean`. Исходное преобразование ID и точность numeric
проверяются на сервере. Технические ID и client key скрыты. Код клиента
видим только на подтверждённых detail-страницах по BR-017.

## Связи

Общие `Календарь`, `Клубы`, `Виды деятельности`, `Сотрудники` и
`Номенклатура` связываются `1:*`, single direction, с каждым применимым
фактом. Fact-to-fact, M2M и двунаправленные связи запрещены. Внешние бюджет,
мероприятия и классификатор услуг фильтруются только доступными общими
измерениями.

## Граница вычислений

PostgreSQL: fixed-классификации, знаковые количество/выручка, age category,
квалификация ИП и плановые назначения. DAX: выручка, количество, средний чек,
УЧК, регулярность, вовлечённость, Renew, MTD/LY и план-факт. Power Query:
Import/типы/русские имена и малые external-наборы.

## Условия принятия

Каждый факт проходит собственную уникальность и reconciliation; общие
измерения уникальны; суммы не размножаются; distinct клиента совпадает на
клубе и сети; шесть KPI и Renew воспроизводят контрольный полный/неполный
месяц; refresh укладывается до 08:30.
