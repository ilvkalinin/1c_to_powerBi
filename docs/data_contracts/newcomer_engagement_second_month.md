# Data contract: «Вовлечение новичков Второй месяц»

Статус: `IMPLEMENTED / RECONCILED / RERUN PASSED — 2026-08-25 / Power BI deferred by BR-036`.

SV-076 подтвердил physical sources, bounded second-month interval и ключ
контрольной выборки, но не уникальность child-кандидата и one-to-one match
СПТ. Контракт сохраняет current source-логику по BR-018; физических объектов
не создавалось.

|---|---|---|---|---|

| `Клубы[ID клуба]` | `Вовлечение новичков Второй месяц[ID клуба доступа]` | `1:*` | однонаправленная | CONFIRMED BY DESIGN; club uniqueness pending |

Связь по коду контракта или клиента не создаётся. Many-to-many и
двунаправленная фильтрация не допускаются. Возраст и группа посещений —
атрибуты факта; отдельные физические измерения для них не требуются.

## Граница PostgreSQL и Power BI

PostgreSQL:

- выполняет текущий утверждённый source-side отбор;
- рассчитывает месяц вовлечения, диапазон второго месяца, `COUNT` строк
  посещений, последнюю дату, группу посещений, возрастную категорию и СПТ;
- возвращает технические ключи и стабильные типы.

DAX:

- число пар клиент-контракт, пары `4+`, долю, прошлый год и прирост;
- плановую долю `доля ПГ + 2 п.п.` и план в штуках с `ROUNDUP`;
- интерактивные фильтры и условное форматирование.

Power Query:

- подключается к готовой таблице, задаёт русские пользовательские имена и
  типы;
- не читает регистры, не объединяет посещения/СПТ и не формирует календарь
  с искусственным сдвигом года.

## Рекомендуемые базовые меры

```DAX
Пары клиент-контракт новичков =
COUNTROWS(
    SUMMARIZE(
        'Вовлечение новичков Второй месяц',
        'Вовлечение новичков Второй месяц'[ID контракта],
        'Вовлечение новичков Второй месяц'[ID клиента]
    )
)
```

```DAX
Пары клиент-контракт новичков 4+ =
CALCULATE(
    [Пары клиент-контракт новичков],
    'Вовлечение новичков Второй месяц'[Группа посещений] = "4+"
)
```

```DAX
Доля новичков 4+ =
DIVIDE([Пары клиент-контракт новичков 4+], [Пары клиент-контракт новичков])
```

Плановая доля и план в штуках остаются мерами. Доли нельзя суммировать по
клубам: их следует пересчитывать из числителя и знаменателя.

## Не включать

- сырые строки `AccumRg7575`;
- дату рождения;
- отдельный Excel-план и его текстовые связи;
- искусственную таблицу `_Даты 2023`;
- отдельные таблицы посещений, контрактов и СПТ для этого отчёта;
- неиспользуемый загрузочный запрос `ВсеПосещения`.

## Условия принятия

1. Уникальность `(contract_id, client_id, month_of_engagement)`.
2. Ровно один результат на подтверждённую пару контракт × клиент × месяц либо
   документированная причина исключения.
3. Для контракта от 21.04.2026 считаются только посещения 01.05–31.05.
4. Результат `COUNT` и `MAX` совпадает с текущим SQL на контрольной выборке.
5. Текущие фильтры SQL, возрастная категория и СПТ воспроизводятся без
   дополнительной интерпретации.
6. KPI считает пары `(contract_id, client_id)`, а не сумму строк, кодов
   контрактов или посещений разных клиентов.
7. Повторный bounded rebuild при неизменном источнике даёт тот же результат.
8. Измерены объём, source-side время, передача между VM и время refresh Power
   BI до определения SLA и индексов.
