Fact-to-fact, двунаправленные и many-to-many связи не используются. Внешняя
таблица `План рецепции` фильтруется теми же справочниками даты, клуба и вида
деятельности, если эти поля присутствуют в Excel. Она не присоединяется к
факту и не фильтруется продавцом без соответствующего поля плана.

## Меры DAX

```DAX
Выручка факт =
SUM('Выручка рецепции'[Выручка])
```

```DAX
Количество услуг =
SUM('Выручка рецепции'[Количество])
```

```DAX
Средняя цена услуги =
DIVIDE([Выручка факт], [Количество услуг])
```

```DAX
Накопительный план =
CALCULATE(
    SUM('План рецепции'[План на день]),
    DATESMTD('Календарь'[Дата])
)
```

```DAX
Накопительный факт =
CALCULATE(
    [Выручка факт],
    DATESMTD('Календарь'[Дата])
)
```

```DAX
Выполнение плана =
DIVIDE(
    [Выручка факт],
    SUM('План рецепции'[План на день])
)
```

`Выполнение плана` передаёт KPI-карточке отношение `Факт / План`; карточка
сама показывает коэффициент прироста относительно цели.

```DAX
Отклонение от плана =
[Выручка факт] - SUM('План рецепции'[План на день])
```

```DAX
Прогноз выручки =
VAR MinSelectedDate =
    MINX(ALLSELECTED('Календарь'[Дата]), 'Календарь'[Дата])
VAR MaxSelectedDate =
    MAXX(ALLSELECTED('Календарь'[Дата]), 'Календарь'[Дата])
VAR OneMonthSelected =
    YEAR(MinSelectedDate) = YEAR(MaxSelectedDate)
        && MONTH(MinSelectedDate) = MONTH(MaxSelectedDate)
VAR MonthStart =
    DATE(YEAR(MaxSelectedDate), MONTH(MaxSelectedDate), 1)
VAR FactMTD =
    CALCULATE(
        [Выручка факт],
        DATESBETWEEN('Календарь'[Дата], MonthStart, MaxSelectedDate)
    )
RETURN
    IF(
        OneMonthSelected,
        DIVIDE(FactMTD, DAY(MaxSelectedDate))
            * DAY(EOMONTH(MaxSelectedDate, 0)),
        BLANK()
    )
```

Доля выручки остаётся контекстной DAX-мерой и не хранится в PostgreSQL.

## Граница вычислений

PostgreSQL:

- квалифицирует движения и исключения;
- определяет продавца отдельно от исполнителя;
- защищает сумму от двойного учёта двух регистров;
- присваивает категории по стабильным ID;
- агрегирует количество и выручку до контрактной гранулярности.

Power Query:

- подключается к готовому view;
- назначает типы и русские имена;
- не выполняет joins, текстовую классификацию и группировки.

DAX выполняет среднюю цену, доли, MTD, KPI и прогноз.

## Не включать

- код, ФИО и дату рождения клиента;
- контракт и тип оплаты;
- исполнителя услуги вместо продавца;
- среднюю цену, долю, прогноз и накопительные итоги как колонки;
- внешнюю Excel-таблицу плана в PostgreSQL;
- отдельные факты для пяти страниц;
- полные копии `AccumRg7575` и `AccumRg7646`.

## Условия принятия

1. Подтверждение продавца и кардинальности связи с чеком.
2. Уникальность технического и агрегированного ключей.
3. Сверка количества и выручки по каждому регистру.
4. Доказательство отсутствия двойного учёта.
5. Проверка отрицательных движений, отмен, удалений и корректировок.
6. Полнота категорий и исключений по ID.
7. Проверка схемы и фильтрации Excel-плана.
8. Контрольные значения карточек и рейтингов.
9. Измерение объёма, времени загрузки и времени чтения view.
