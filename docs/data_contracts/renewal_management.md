## Связи

| От | К | Кардинальность | Фильтрация |
|---|---|---|---|
| `Календарь[Дата]` | `Управление продлением[Дата окончания]` | `1:*` | однонаправленная |
| `Клубы[Код клуба]` | `Управление продлением[Код клуба доступа]` | `1:*` | однонаправленная |

Дата продления не получает вторую активную связь с календарём. При отдельной
аналитике по ней используется неактивная role-playing связь и
`USERELATIONSHIP`.

## Меры DAX

```DAX
Заканчивается =
DISTINCTCOUNT('Управление продлением'[Технический код абонемента])
```

```DAX
Продлено на 1-е =
CALCULATE(
    [Заканчивается],
    'Управление продлением'[Продлен на 1-е] = TRUE()
)
```

```DAX
Продлено на сегодня =
CALCULATE(
    [Заканчивается],
    'Управление продлением'[Продлен на сегодня] = TRUE()
)
```

```DAX
%Renew на 1-е =
DIVIDE([Продлено на 1-е], [Заканчивается])
```

```DAX
%Renew итоговый =
DIVIDE([Продлено на сегодня], [Заканчивается])
```

```DAX
Поздно продлено =
[Продлено на сегодня] - [Продлено на 1-е]
```

```DAX
Прирост Renew после 1-го =
[%Renew итоговый] - [%Renew на 1-е]
```

Медиана дней возврата считается явной DAX-мерой только по продлённым
контрактам с непустым `Дней возврата`.

## Граница вычислений

PostgreSQL выполняет joins, отбор когорты, выбор следующего абонемента,
контрактную посещаемость, цену, latest-атрибуты и строковые флаги.

Power Query только подключается, назначает типы и русские имена.

DAX выполняет проценты, прошлый год, цель, дефицит, поздние продления и
медиану.

## Не включать

- Excel и snapshots;
- сырые движения посещений и расчётов;
- отдельные таблицы цены, стажа, рейтинга и взаимодействия;
- месяц в ключе абонемента;
- двунаправленные `1:1`;
- проценты Renew как физические колонки.

## Условия принятия

1. Уникальность контрактной строки.
2. Контроль двух Renew-флагов на граничных датах.
3. Сверка когорты и продлений с текущим отчётом.
4. Проверка next-contract и возвратов.
5. Сверка посещений, цены и latest-атрибутов.
6. Контроль отсутствия размножения joins.
7. Измерение времени ежедневной полной замены.
8. Проверка прав доступа к PII.

SV-081 дал bounded source-side доказательство ключа, legacy-исключений,
next-start tie, latest rating/tenure, цены и единицы посещений. Он не закрывает
условия принятия для всей популяции и не разрешает реализацию.
