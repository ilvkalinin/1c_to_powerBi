## SV-125 — «Поступления» и «Членство для правления»: разные current-DAX когорты цены и длительности

Статус: `VALIDATED CURRENT-DAX RISK / PRESERVE BY BR-018`. Выполнен 2026-08-19
локально по exact `DataModelSchema` действующего
[PBIT](../source_reports/membership_receipts/Отчет%20по%20поступлениям.pbit).
Серверный запрос здесь не нужен: различие задаётся самим DAX, а не состоянием
источника.

`ЦенаКонтр ФактФизкульт` читает `Таблица Активных Контрактов`. Эта таблица
создана из авансов только при трёх условиях: длительность больше 28 дней,
тип оплаты не «Услуга» и `_ИтогоПоКонтракту <> 0`; цена затем агрегируется по
`contract × payment_period`. Напротив, `Прод Факт` читает исходные «Авансы
по контрактам»: её `FilteredTable` содержит только первые два условия, а
`SUMMARIZE` строится от исходной таблицы и в подтаблице отбирает строки только
по договору. Следовательно, это не одна и та же когорта даже до учёта
club-specific правил цены.

Это не дефект, который можно исправить на Stage 2: единая когорта изменила бы
существующие результаты. По BR-018 различие сохраняется как критичный
артефакт возможной методической доработки. В будущем физическом слое цена и
длительность должны иметь раздельно документированные базы; выбирать новый
общий grain, tie-break цены или иной DAX нельзя без отдельного решения.

SV-115 остаётся действующим ограничением внутри текущей цены: несколько
ценовых пар на договор не получают нового tie-break. После SV-125 незакрытыми
частями MR-V11 остаются роли дат и полный KPI-total, а также rerun и SLA.

## SV-126 — «Поступления» и «Членство для правления»: current-DAX роли дат

Current DAX использует дату движения для рекарринга и обеих service-веток,
дату активации — для предоплаты/бесплатного типа, а дату окончания включает
только отдельными ending-мерами через `USERELATIONSHIP`. В таблице ниже
показаны исходные строки текущих веток, не договоры.

| Ветка / тип оплаты | Строки | Дата поступления вне BR-003 | Нет даты для расчёта | Дата для расчёта вне BR-003 | Конец раньше начала |

| Обычные авансы / предоплата | 183 878 | 0 | 0 | 23 706 | 4 809 |
| Обычные авансы / рекарринг | 21 024 | 0 | 0 | 0 | 80 |
| Авансы по полотенцам / услуга | 2 355 | 0 | 0 | 0 | 14 |

Все source-движения отобраны по периоду `[2025-01-01, 2027-01-01)`. Выход
даты активации за эти границы у предоплаты и бесплатного типа ожидаем: он
следует current-DAX роли даты, поэтому его нельзя обрезать датой загрузки.
Во всех ветках дата для расчёта заполнена. У 74 961 service-строки нет
карточки договора и поэтому нет дат начала/окончания; current M сохраняет их

но 4 919 строк имеют окончание раньше начала. Это не исправляется: current
`Таблица Активных Контрактов` требует `DATEDIFF(start, end) > 28` и потому
такие строки в её price/duration KPI не входят; receipt/service факт сохраняет
их по своей роли даты.

SV-126 закрывает MR-V12 как проверку текущих ролей и физических входов. Он не
сверяет общий KPI-total и не создаёт новый календарный фильтр, rerun или SLA;
Stage 3 остаётся закрыт global gate.
