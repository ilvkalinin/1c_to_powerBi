# ADR-0025: общий факт тренировок ИП

- Статус: `DESIGNED / BLOCKED BY TECHNICAL VALIDATION / IMPLEMENTATION DEFERRED`
- Дата: 2026-08-03
- Отчёты: №8 «Отчёт по ИП», №1 «KPI Фитнеса», №6 «Загрузка сотрудников», №29 «Выручка ДПФУ»

## Решение

Целевой объект — физическая таблица `mart.ip_training_daily` с grain:

> дата тренировки × клуб × сотрудник × защищённый клиент × услуга.

Ключ — полный состав grain; `training_count` хранит число квалифицированных
строк текущей M/PBIT-логики. `SV-058` доказал 227 добавочных legacy-строк
ветки ПЗ из-за `VT4352`; по BR-018 первый релиз сохраняет их, а не выполняет
скрытую дедупликацию до логических тренировок. Факт REUSE
всеми четырьмя потребителями; отдельный IP-count в `visit_client_day` и копии
по отчётам запрещены.

Source-side запрос определяет ветку ПЗ/ГП, воспроизводит текущую кратность
`VT4352` и применяет подтверждённые состояния. Затем агрегат атомарно
загружается на VM-2. Постоянный staging/core не создаются. Физическая
таблица выбрана из-за раздельных VM и повторного использования; view или
materialized view не выбираются без измерений.

## Обновление и Power BI

Ежедневный bounded rebuild BR-003. PostgreSQL квалифицирует тренировку и
считает `training_count`; DAX считает услуги, УЧК, тренеров, регулярность и
доли. Код клиента включается только в модель отчёта ИП/KPI с подтверждённой
детализацией; технические ключи скрыты.

## Блокер реализации

До SQL нужно проверить полиморфную ссылку, полноту source states, физические
типы, объём и контрольные значения итогового агрегата. `VT4352` уже измерена
SV-058; нормализация до уникальных событий является отдельным улучшением и
не меняет первый релиз без нового решения.
