# ADR-0023: использования карты администратора

- Статус: `IMPLEMENTED / INITIAL BR-003 LOAD VALIDATED — AC-REC-001—002`
- Дата: 2026-08-03
- Отчёт: №25 «Карта администратора»

## Решение

Создать физическую таблицу `mart.administrator_card_gymmy_daily` только для
Gymmy с grain:

> дата × клуб × направление.

Сырые события и коды карт не переносятся. Внешний Excel «Журнал
администратора» остаётся в Power BI; Power Query выполняет только малый append
двух уже агрегированных наборов к общей семантической таблице
`Использования карты администратора` с grain
`дата × клуб × направление × источник × причина`.

Такое решение сохраняет правило проекта об external-файлах и не требует
загрузки пользовательского Excel в PostgreSQL. Постоянный staging/core,
materialized view и отдельные факты входа/выхода не создаются.

## Обновление и граница

Gymmy-таблица обновляется ежедневно полным bounded rebuild BR-003. PostgreSQL
фильтрует успешность, сопоставляет 12 кодов карт клубам и агрегирует события.
Power Query нормализует малый Excel и append; DAX считает входы, выходы и
разницы.

## Риски

SV-002 подтвердил существование `public._inforg5836`; SV-100/AC-V05 —
соответствие кодов клубам, тип успешности и source-side правила. Начальная
загрузка 2026-08-19 прошла в одном repeatable-read source snapshot:
`Вход = 107583`, `Выход = 86694`; целевые key/contract/horizon controls = 0.
Схема Excel не анализируется по границе проекта и не является серверным
блокером PostgreSQL-объекта.
