# ADR-0031: ежедневный знаменатель клиентской базы

- Статус: `ACCEPTED / SCHEMA IMPLEMENTED / INITIAL LOAD NOT REQUESTED`
- Дата: 2026-08-19
- Потребители: «Работа с посещаемостью», KPI Фитнеса, «Титульный лист»

## Контекст

Редкий снимок `mart.client_base_snapshot` не подходит для показателя
«% посещений от КБ»: расчёт использует среднее значение базы по каждому
выбранному календарному дню. Обычный сетевой итог нельзя получить суммой
клубов: один клиент может состоять в нескольких клубах. SV-111 подтвердил
точное current-M правило на всём горизонте BR-003 и равенство interval-
контроля прямому `COUNT(DISTINCT)` на четырёх датах.

## Решение

Создать один самостоятельный факт `mart.client_base_daily` с grain:

> уровень охвата × календарная дата × клуб только для уровня `club` × возраст
> × возрастная группа × пол.

Уровень `club` считает уникального клиента в его клубе, `network` — один раз
во всей сети; `club_id` обязателен только для `club`. Значение базы —
`client_count`. Возрастная группа и пол нормализуются в источнике; неизвестный
возраст или пол обозначается `Не указано`. Состояние на дату D сохраняет
BR-005: `active_from < D` и `active_to >= D - 1`.

Не создаются второй daily-факт для KPI/титульного листа, постоянный staging,
client-level таблица или таблица под конкретный визуал. `client_base_snapshot`
и `client_base_retention` имеют иной набор разрезов и остаются вне этого
пакета.

## Граница Power BI

Power BI импортирует готовые семь полей. Календарь и клубы фильтруют факт
`1:*`, в одну сторону. DAX выбирает `club` при фильтре клуба и `network` без
него, затем считает среднее `client_count` по выбранным дням. DAX не делает
distinct клиентов, объединение интервалов, расчёт возраста или дедупликацию
уровней охвата.

## Обновление

Первый релиз проектируется как полный атомарный rebuild BR-003. На VM-1
клиент используется только во временном source-side наборе; на VM-2 попадают
только агрегаты. Никакой watermark не заявляется до отдельной проверки
изменений и rerun. Перед начальной загрузкой отдельно подтверждаются точный
extract, source/target controls и SLA до 08:30.
