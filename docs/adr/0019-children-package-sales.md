# ADR-0019: продажи детских пакетов

- Статус: `DESIGNED / BLOCKED BY TECHNICAL VALIDATION / IMPLEMENTATION DEFERRED`
- Дата: 2026-08-03
- Отчёт: №15 «Продажа детских пакетов»

## Решение

Целевой объект — физическая таблица `mart.children_package_sale` с grain:

> одна строка дополнительного пакета одного ребёнка в одном чеке.

Логический ключ `(receipt_id, package_line_no)`. В таблицу входят только
подтверждённые поля текущих страниц: дата, клуб, взрослый контракт, взрослый и
ребёнок, продукт, знаковые сумма/количество и `sold_correctly_flag`.

Универсальный факт продаж не создаётся: поступления, рецепция и ДПФУ имеют
другие grain и правила признания. Source-side запрос должен сначала доказанно
связать `VT4913` с единственной стоимостью/номенклатурой; затем компактный
результат атомарно загружается на VM-2. Постоянный staging/core не создаются.

Физическая таблица выбрана из-за раздельных VM и повторных сложных joins.
View/materialized view не выбираются без измерений.

## Обновление и Power BI

Ежедневный bounded rebuild BR-003 без неподтверждённого watermark. PostgreSQL
рассчитывает знак возврата и корректность продажи. DAX считает количество,
сумму, выбранные стоимости, динамику и рейтинг клубов. Технические ключи
скрыты; подтверждённая detail доступна пользователям отчёта по BR-017.

## Блокер реализации

До SQL требуется доказать однозначную связь строки ребёнка с продуктом и
суммой, знак возврата и source states. Если связь не `1:1`, архитектура
пересматривается на bridge строки чека; произвольный `MIN/MAX` запрещён.
