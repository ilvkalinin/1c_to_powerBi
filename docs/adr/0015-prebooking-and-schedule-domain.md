# ADR-0015: общий домен предзаписи, групповых занятий и расписания

- Статус: `IMPLEMENTED / initial BR-003 load VALIDATED — S3-LS-001—003`
- Дата: 2026-08-03
- Отчёты: №7 «Контроль предварительной записи», №10 «Уроки и расписание»

## Контекст

Два отчёта повторно используют документы персональных и групповых занятий,
но нуждаются в трёх grain: история состояния записи, одно групповое занятие и
занятие, развёрнутое по пятиминутным слотам. Детальный дневной план уже имеет
точно тот же grain, который нужен контролю предзаписи.

## Решение

После технической валидации создать:

- `mart.prebooking_state_event` — одно событие состояния одной записи;
- `mart.group_lesson` — одно групповое занятие с вместимостью и итогами
  записей/прибывших;
- `mart.lesson_room_slot_5m` — одно занятие из `Document279/329` × один
  пятиминутный слот;
- REUSE `mart.dpfu_plan_assignment`, а не отдельную копию плана.

Каждый новый объект — физическая компактная таблица на VM-2. Source-side
запросы сначала нормализуют полиморфные ссылки и one-to-many табличные части.
Постоянный общий staging не создаётся. Слот-факт не заменяет lesson-факт:
вместимость и количество записей нельзя повторять в каждом слоте.

## Обновление и Power BI

Ежедневный атомарный rebuild горизонта BR-003 до подтверждения watermark.
Общие календарь, клуб, сотрудник, услуга, вид деятельности и помещение
фильтруют факты однонаправленно. Связь `group_lesson → state_event` допустима
только как `1:*` по технически подтверждённому ID; в Power BI предпочтительны
общие измерения, а не fact-to-fact.

PostgreSQL хранит категории своевременности, booking delta, вместимость,
пришедших и пятиминутные слоты. DAX считает нетто-записи, доли, рейтинги,
заполненность и интерактивную занятость. Внешние справочники помещений и
параметры остаются в Power BI.

## Уточнение slot-факта — 2026-08-14

`mart.lesson_room_slot_5m` — physical table на VM-2 с ключом
`(source_kind, source_lesson_id, slot_start_at)`. Обновление — атомарный
полный BR-003 rebuild без постоянного staging: узкий source extract
передаётся binary COPY непосредственно в целевую таблицу внутри одной target
transaction. Это устраняет вторую запись 5,4 млн строк и не создаёт реплику
1С. Единственный индекс — primary key; дополнительный индекс не вводится без
измеренного Power BI-плана.

BR-021 является явным исключением к точной границе `[start,end)`: каждый
положительный неполный интервал получает последний полный пятиминутный слот,
который может закончиться до четырёх минут позже `lesson_end_at`. Два
неположительных интервала не создают строк и проверяются в source control.
Вместимость, записи и пришедшие не повторяются на слотах и остаются в
`mart.group_lesson` / `mart.prebooking_state_event`.

## Риски

Ключ/история `InfoRg7006`, полиморфная ссылка, `VT4352`, состояния документов,
ключ плана и уникальность занятия — `VALIDATION_PENDING` только у иных
потребителей. Для slot-факта source ID, интервалы, cardinality и ветви
подтверждены SV-LS-001. Orphan dimensions остаются `NULL`; существующий
дефект service-filter в loader `mart.group_lesson` записан как отдельная
возможная доработка и не меняется этим пакетом.

## Initial load — 2026-08-14

После отдельных DDL и DML approvals `mart.lesson_room_slot_5m` загружена
атомарно из одного source snapshot. `S3-LS-001—003` прошли: 5 424 234 строки,
в том числе 1 968 061 ГЗ и 3 456 173 ПЗ; source-to-target snapshot controls,
BR-003, обязательные поля, slot position и расчёт количества слотов BR-021
для каждого занятия совпали. Все mismatch counts = 0.
