# ADR-0024: составная модель «Титульного листа»

- Статус: `DESIGNED / TECHNICAL VALIDATION COMPLETE / IMPLEMENTATION DEFERRED`
- Дата: 2026-08-03
- Отчёт: №26 «Титульный лист»

## Решение

Отдельная PostgreSQL-витрина титульного листа не создаётся. Power BI REUSE:

- `mart.revenue_group_summary_daily` для доходных статей;
- `mart.client_base_daily` для КБ;
- `mart.club_attendance_hourly` для максимальной ЧК;
- текущий внешний Renew и внешние свойства/расходы/мощности клуба.

Общие календарь и клуб фильтруют каждый факт однонаправленно. Двунаправленные
связи текущего PBIT для площадей/мощности заменяются на `Клубы 1:* внешний
факт`; fact-to-fact и универсальная «строка титульного листа» запрещены.

## Обновление и граница

Отчёт обновляется еженедельно, используя последние согласованные версии
ежедневных витрин. PostgreSQL не рассчитывает готовую карточку. DAX выполняет
композицию выручки, доли, на квадратный метр, выбранный месяц, Renew и
максимальную ЧК. Power Query только подключает факты и сохраняет малые внешние
таблицы.

## Риски

Категории доходов и current почасовая ЧК титульного листа подтверждены в
SV-062—SV-064. Daily-КБ остаётся зависимостью собственного продукта, а
`active_base_rate` — текущим внешним показателем Power BI и не выводится из
PostgreSQL без отдельного mapping.
