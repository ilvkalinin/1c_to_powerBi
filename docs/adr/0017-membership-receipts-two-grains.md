# ADR-0017: поступления по членству — движение и контрактная KPI-единица

- Статус: `DESIGNED / TECHNICAL VALIDATION REQUIRED / IMPLEMENTATION DEFERRED`
- Дата: 2026-08-03
- Отчёты: №13 «Отчёт по поступлениям», №30 «Членство для правления»

## Контекст

Сумма поступлений имеет grain движения, а количество/цена/длительность —
grain контракта предоплаты либо ежемесячного рекаррингового платежа. Попытка
обслужить пять KPI одной строкой уже создаёт разные роли дат и знаменатели.

## Решение

Создать две физические таблицы:

- `mart.membership_receipt_movement` — квалифицированное денежное движение,
  ключ-кандидат `(source_kind, recorder_id, recorder_line_no)`;
- `mart.membership_contract_kpi_unit` — одна KPI-единица: контракт
  предоплаты либо ежемесячный платёж рекарринга, ключ `kpi_unit_key`.

Общие contract attributes вычисляются source-side один раз в временном наборе
одной загрузки; постоянный `core` не создаётся до появления другого
потребителя того же полного набора. `Свод выручка ГК` повторно использует
source-rule и reconciliation, но не эти детальные таблицы. Отчёт для
правления REUSE обе таблицы без отдельной копии.

Физические таблицы выбраны из-за раздельных VM, полиморфных документов и
повторных сложных as-of/price вычислений. Удалённый view и materialized view
не выбираются без измерений.

## Обновление и Power BI

Ежедневный атомарный rebuild BR-003; event/activation dates не считаются
watermark. Движение связано с активным календарём поступления, KPI-единица —
с активным календарём `metric_date`; дата окончания — отдельная неактивная
роль. Клуб доступа, клуб продажи и менеджер должны фильтровать оба
соответствующих факта однонаправленно.

PostgreSQL рассчитывает sign, source kind, payment type, super stage,
duration, price helpers и ключ KPI. DAX считает пять KPI, средние и временные
сравнения. Excel-планы остаются отдельными Power BI-фактами.

## Риски

Ключ рекаррингового платежа, source states/signs, predecessor ties, price and
freeze joins — `VALIDATION_PENDING`. Без доказанного `kpi_unit_key` второй
объект не реализуется; это технический блокер реализации, не изменение
подтверждённого бизнес-grain.
