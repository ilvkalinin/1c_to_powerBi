## Метрики

| Метрика Power BI | Бизнес-определение | Текущая реализация | Статус |
|---|---|---|---|
| `Кол-во услуг` | количество занесённых тренировок за выбранный период | `COUNT('Общая'[Контрагент])` | CONFIRMED current |
| `УЧК` | уникальные клиенты, потребившие услуги | `DISTINCTCOUNT('Общая'[Контрагент])` | CONFIRMED current / key correction proposed |
| `Регулярность` | услуги / УЧК | `DIVIDE([Count], [dCount])` | CONFIRMED |
| `Тренеров` | уникальные ИП, занёсшие тренировки | `DISTINCTCOUNT('Общая'[Сотрудник])` внутри меры услуг на тренера | CONFIRMED current / key correction proposed |
| `Услуг на 1 тренера` | услуги / тренеры | `DIVIDE([Count], DISTINCTCOUNT('Общая'[Сотрудник]))` | CONFIRMED |
| `Доля услуги` | услуги выбранного типа / все услуги в том же контексте клуба и месяца | показана визуалом; DAX не предоставлен | CONFIRMED need / DAX can be redesigned |

Текущие distinct-меры используют отображаемые наименования контрагента и сотрудника. Целевая модель должна считать по стабильным ключам клиента и сотрудника: совпавшие ФИО не должны объединять разных людей, а переименование не должно менять историю.

## Требуемая детализация

Визуалы должны поддерживать одновременно:

- день и клуб;
- сотрудника;
- тип услуги;
- клиента с отображением `КодКлиента`;
- несколько тренировок одного клиента в одном периоде.

Поэтому общий факт `дата × клуб × клиент` из посещенческих отчётов недостаточен. Он потеряет сотрудника, услугу и повторные тренировки.

Минимальная целевая гранулярность результата:

> дата тренировки × клуб × сотрудник × клиент × услуга.

В строке хранится количество квалифицированных тренировок этой комбинации.
Индивидуальный идентификатор и время каждой тренировки Power BI не нужны. До
агрегации PostgreSQL должен воспроизвести текущую кратность строк двух ветвей
M/PBIT. `SV-058` уже подтвердил, что ветка ГП не размножается, а ветка ПЗ
содержит 227 добавочных legacy-строк join; по BR-018 первый релиз сохраняет
именно текущий `COUNT(Контрагент)`, а не скрыто заменяет его числом уникальных
событий. Нормализация до уникальной логической тренировки — отдельное
методическое улучшение, а не блокер воспроизведения.

## Повторное использование

Обе ветви источника уже используются мерой `Посещения ИП` в отчёте «Посещения Физкульт». После технической проверки временного ключа один общий факт тренировок ИП должен обслуживать:

- весь отчёт «Отчет по ИП»;
- показатель `Посещения ИП` в отчёте «Посещения Физкульт»;
- потенциально будущие отчёты «Загрузка сотрудников», «Контроль предварительной записи» и «Уроки и расписание» — только после проверки их запросов.

Отдельную копию данных для каждого из этих отчётов создавать не следует.

Предварительное пользовательское имя таблицы Power BI: `Тренировки ИП`. Все поля и меры модели должны иметь русские пользовательские названия.

## Подтверждённые решения 2026-07-24

1. Оставить текущий отбор состояний: исключать `EnumOrder = 2` и `EnumOrder = 3`.
2. День и месяц определять по `ВремениНачала`: запись в регистр может быть внесена когда угодно.
3. Обновлять один раз в день.
