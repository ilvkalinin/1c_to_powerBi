# S3-REVENUE-CHAIN-001: единый дневной refresh доходного контура

Дата согласования: 2026-08-20. Статус: `COMPLETED`.

Пользователь подтвердил единый fail-closed запуск уже reviewed loaders в
порядке их зависимостей, чтобы summary не использовал устаревший shared scope.

## Scope

1. Создать локальный runner, который строго последовательно запускает
   existing loaders: `dpfu_ancillary_revenue` → `reception_revenue` →
   `ip_revenue_daily` → `revenue_group_summary`, передавая им существующую
   конфигурацию и `--apply`.
2. Прервать цепочку при первом ненулевом коде, вывести без секретов статус,
   длительность и итог каждого этапа; после успеха записать единый журнал
   длительностей и controls.
3. Выполнить один end-to-end прогон и повторный контрольный запуск runner.
   Все DML остаются только теми же атомарными DML reviewed loaders; DDL,
   Power BI, Excel, scheduler, source 1С и новая бизнес-логика исключены.

Техническая адаптация для сохранения существующего scope: DPFU loader заменяет
только `revenue_scope = 'dpfu'` и проверяет отсутствие collision с `reception`;
ранее он заменял весь shared факт. Это не изменяет DPFU extract, columns,
grain или controls и необходимо для корректного порядка цепочки.

## Уточнение SLA от пользователя

`2026-08-20`: это и все существующие loaders в данной цепочке являются
редкими полными пересборками. Их длительность измеряется отдельно и не
сравнивается с минутным ежедневным SLA. Для **всех** витрин проекта цель
ежедневного обновления — инкрементальный refresh не более одной минуты; он
должен быть отдельным пакетом с подтверждённым watermark, обработкой
изменений/удалений и reconciliation, а не замаскированной полной
перезагрузкой.

## Критерий закрытия

Каждый этап проходит свой existing source/stage/target/rerun contract;
summary использует обновлённые shared scopes; оба end-to-end запуска завершаются
без ошибок, а зафиксированы полная длительность и вклад каждого этапа.
