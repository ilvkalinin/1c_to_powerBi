## Назначение и решения

Отчёт показывает поступления от членства и связанных услуг, количество
контрактов, цену и длительность контрактов в разрезах сети, клуба, времени,
стажа, возраста, типа оплаты, канала продажи и параметров номенклатуры.
Факт сравнивается с прошлым годом, среднесрочным и текущим планами.

Подтверждённые решения, поддерживаемые отчётом:

- оценка выполнения плана поступлений и количества по клубам и ресурсам;
- сравнение средней цены контракта, средней цены месяца и продолжительности с
  планом и прошлым годом;
- рейтинг клубов и менеджеров;
- анализ структуры продаж по параметрам контракта и номенклатуры;
- поиск сочетаний с отклонением от плана.

Конкретные роли пользователей в материалах не названы. По содержанию
страниц подтверждены потребители уровня руководителей продаж, руководителей
клубов и менеджеров. Клубные и менеджерские разрезы доступны всем
пользователям с доступом к отчёту (решение пользователя 2026-07-31, BR-017);
внутреннее RLS-ограничение не задано. Потребитель клиентских ФИО на показанных
страницах отсутствует, поэтому PII не включается в целевой Power BI-контракт.

## Пять ключевых показателей: текущая логика

### 1. Поступления всего

`CONFIRMED current DAX`: мера `Пост Факт` складывает два набора:

1. движения `AccumRg7370` по контрактам после текущей классификации
   регистраторов, знака и вычета со-доступа;
2. движения `AccumRg7739` только по текущему текстовому перечню услуг:
   со-доступ, полотенца, гостевой визит, заморозка, переоформление, адаптация
   ДРЦ и вход для детей.

Дата показателя — `Period::date` движения. Для контрактной ветки клуб —
основной клуб доступа. Для услуг клуб движения используется всегда, кроме
со-доступа: он относится к основному клубу доступа контракта.

`CONFIRMED user decision 2026-07-31`: это окончательная граница показателя.
В «Поступления всего» входят только деньги, связанные с покупкой и
обслуживанием членства. Бар, фитнес-услуги, солярий, массаж и прочие
немembership-направления исключаются.

### 2. Количество

`CONFIRMED current DAX`: сначала остаются контракты:

- длительность между датами начала и окончания больше 28 дней;
- тип оплаты не `Услуга`;
- полный итог по `contract_id × analytics_sequence` не равен нулю.

`CONFIRMED user decision 2026-07-31`: бизнес-единица зависит от типа оплаты:

- обычный абонемент с предоплатой считается один раз: один контракт — одна
  продажа;
- у рекарринга каждый квалифицированный ежемесячный платёж считается одной
  единицей, потому что рекарринговое продление происходит ежемесячно;
- membership-услуги из денежного контура не входят в контрактное количество.

Текущий `analytics_sequence` является кандидатом идентификатора
рекаррингового платежа. Его соответствие одному реальному ежемесячному
платежу — `VALIDATION_PENDING`, а не бизнес-решение.

### 3. Средняя цена контракта

`CONFIRMED target rule`: сумма расчётной цены делится на подтверждённое
количество квалифицированных единиц: контрактов предоплаты и ежемесячных
платежей рекарринга.

- для клубов Физкульт используется чистая сумма поступлений;
- для Пушкинского/Пушкинского VIP используется цена контракта из
  `_Спр Абонементы.price`;
- для рекарринговых строк со стажем `Продажа`/`Списание` используется чистая
  сумма поступлений независимо от клуба.

`СуммаНовыйФинал` берётся как связанное значение цены контракта; при
нескольких строках DAX использует `MINX`. Физическая кардинальность этой цены
`VALIDATION_PENDING`.

### 4. Продолжительность

`CONFIRMED current DAX`: среднее по квалифицированным контрактным единицам,
затем перевод дней в месяцы делением на `30.42`.

- услуги исключаются;
- контракт должен быть длиннее 28 календарных дней;
- рекарринг всегда получает `30.42` дня, то есть один месяц;
- предоплата получает `Reference59.Fld693 + free_freeze_before_activation`;
- платные дни заморозки вычитаются из общей заморозки до активации;
- контракт включается, если рассчитанная чистая сумма больше нуля.

### 5. Средняя цена месяца

`CONFIRMED current DAX`:

> средняя цена контракта / средняя продолжительность в месяцах.

Это мера фильтр-контекста, а не сохранённая колонка. Нельзя усреднять готовые
результаты по строкам или месяцам повторно.

## Стаж

Целевой `Супер_стаж` вычисляется, а не берётся напрямую из `Reference59`:

- membership-услуга → `Клип-карты`;
- рекарринг с аналитической последовательностью `1` → `Продажа`, остальные
  последовательности → `Списание`;
- Renew с разрывом более нуля календарных месяцев → `RENEW(БП)`;
- EX с предыдущим окончанием более чем за 180 дней до активации → `NEW`;
- начало в том же месяце, что окончание предыдущего контракта → `RENEW`;
- остальные случаи сохраняют исходный `NEW/RENEW/EX`.

`CONFIRMED user decision 2026-07-31`: публичный набор состоит из `NEW`,
`RENEW`, `RENEW(БП)`, `EX`, `Продажа`, `Списание`, `Клип-карты`.
`Супер_стаж(НОВЫЙ)` и дополнительное разделение `NEW(ПЧК)/NEW(БЧК)` не
переносятся.

## Возраст и параметры продукта

`CONFIRMED user decision 2026-07-31`: возрастной срез, как и в текущем
отчёте, является категорией номенклатуры, а не возрастом клиента на дату
события. Публичные категории: `Взрослые`, `Дети`, `Юниоры`.

- текущие `Взрослые`, `Дети`, `Юниоры` сохраняются;
- текущие `Детские секции` преобразуются в `Дети`;
- неизвестное значение по текущему правилу относится к `Взрослые`;
- membership-услуги не получают возраст.

BR-008 к этому продуктовому срезу не применяется.

Другие подтверждённые текущие признаки:

- зона доступа определяется по клубу и поиску `VIP/Exclusive/кандидат` в
  названии номенклатуры;
- время доступа — поиск `дневн` либо справочник `InfoRg8595`;
- тип клубного доступа — поиск `сеть` либо `InfoRg8595`;
- вид абонемента — GUID и текстовый признак семейной покупки;
- источник/канал — реквизит документа-регистратора с текстовым override
  `web` в номенклатуре.

`CONFIRMED user decision 2026-07-31`:

- `Кредит` и `Бесплатный` объединяются с `Предоплата`; итоговые типы оплаты —
  `Предоплата`, `Рекарринг`, `Услуга`;
- сохраняются все шесть каналов: `Клуб`, `Website`, `App`,
  `App сотрудника`, `Web customer`, `Рассрочка`, даже если два значения
  фактически не встречаются.
