# Требования отчёта: «Уроки и расписание»

Статус: `BUSINESS LOGIC COMPLETE / ARCHITECTURE DESIGNED — ADR-0015 / TECHNICAL VALIDATION PARTIALLY VALIDATED — SV-073`.

Разбор выполнен локально по описанию отчёта и полному текущему Power Query/DAX.
Подключений к 1С/PostgreSQL, выполнения SQL и создания объектов не было.

## Назначение

Отчёт нужен фитнес-менеджерам для решений по сетке занятий: какие бесплатные
уроки сохранять или менять, как заполнены платные уроки, насколько заняты залы
и как своевременно заносится расписание.

## Подтверждённые страницы и показатели

| Страница | Показатель / представление | Текущий расчёт | Статус |
|---|---|---|---|
| `Загрузка бесплатных уроков` | рейтинг урока | `фактически посетило / плановая вместимость`; вместимость берётся из внешнего справочника площадей и правила `0,9`, с восемью явными исключениями | CONFIRMED current calculation |
| `Посещ-ть ГП (общ)` | доля ГП от посещений | `посетило ГП / посетило клуб`; для большинства клубов знаменатель — женщины-взрослые, для Пушкинского/Пушкинского VIP — все посещения | CONFIRMED current calculation |
| `Посещ-ть ГП (У-Д-В)` | та же доля по времени суток | утро `< 12:00`; день `12:00–16:59`; вечер `>= 17:00` в «Волшебной статистике» | CONFIRMED current calculation |
| `Загрузка МГ и ПУ` | загрузка платного урока | `количество прибывших записей / вместимость занятия` | CONFIRMED current calculation |
| `Загрузка залов` | занятые часы и загрузка | объединение `Document329` и `Document279`, развёрнутое на 5-минутные слоты; `занятые часы / плановые часы` | CONFIRMED current calculation |
| `занесены не в срок` | число и доля поздно внесённых услуг | документ считается поздним, если его `Date_Time` больше времени окончания занятия; доля сейчас делит distinct дат регистрации, а не число услуг | CONFIRMED current calculation; semantic risk |
| `ХУК Уроки ГП` | цвет рейтинга | пороги процента заполнения по времени суток и будни/выходные: `50/60`, `30/40`, `70/90`, затем `100%` | CONFIRMED |

Текущий код использует две разные семантики «платного»: для группового
занятия `РазрешенаЗаписьСНулевойЦеной = 1` означает «Клубное время», а для
предварительной записи `NULL` означает «Резерв». Их объединение сохранено как
текущая логика, но значения и их полнота требуют технической проверки.

## Фильтры и разрезы

Подтверждены: период/год/месяц/день, клуб, подразделение, помещение, тренер,
услуга, время суток и формат тренировки. Для загрузки залов используются также
категория занятия и 5-минутный временной слот. Для страницы ГП есть особый
переключатель «Дети ВП Родионова / Прочие ЧК»; по описанию он фактически
выбирает детей независимо от выбранного подразделения.

## Гранулярность

| Логический набор | Одна строка | Назначение |
|---|---|---|
| `групповое занятие` | одно `Document279` | вместимость, бесплатная посещаемость, рейтинг урока, платные прибывшие |
| `расписание занятия` | один `Document279` или `Document329` | время, зал, тренер, услуга, своевременность внесения |
| `занятость зала` | расписание занятия × 5-минутный слот | часы и структура занятости залов |
| `посещения клуба` | дата × клуб × время суток × возрастная группа × пол | знаменатель доли ГП; текущая ветвь `Посещения2026` |

## История, обновление и контроль

- В текущих запросах история разнородна: с 2023-01-01, 2024-04-01 и только
  2026 год. Целевая история следует единой календарной политике BR-003
  (решение пользователя 2026-07-30).
- Обновление выполняется ежедневно, данные доступны до 08:30 по Москве;
  контрольные значения пока `UNKNOWN` (решение пользователя 2026-07-30,
  BR-014).
- Внешние Excel-справочники площадей, типов уроков, помещений, параметров
  мощности и исторической базы за 2022–2024 остаются внутри модели Power BI
  и не переносятся в PostgreSQL: `CONFIRMED — решение пользователя 2026-07-30`.

## Учёт class-C критичности — 2026-08-13

Новый вопрос пользователю не требуется: BR-018 задаёт воспроизведение current
M/DAX, а SV-073 фиксирует факты, не позволяющие скрытую нормализацию.

- шесть неположительных ГП-интервалов и интервалы, некратные пяти минутам, не
  исправляются и не округляются; разворот в 5-минутные слоты применяется
  только в точных текущих границах `[start_at, end_at)`;
- отмены, `Posted`/`Marked` и payment branches ПЗ/ГП остаются разными current
  ветвями: новый универсальный state-filter не вводится;
- orphan room/employee/service/activity/format не заполняются fallback-значением
  и не исключаются без отдельного методического решения;
- внешние Excel-справочники остаются в Power BI.

Это safeguards первого релиза, а не новые правила расписания.
