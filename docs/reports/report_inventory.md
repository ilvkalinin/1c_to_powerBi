Источник рабочего перечня: `Список отчетов.xlsx`, предоставлен пользователем и прочитан 2026-07-23.

Основной договорный scope: 31 отчёт из изображения договора, подтверждённого пользователем 2026-07-24; см. `docs/reports/contract_scope.md`. Настоящий Excel-инвентарь из 37 строк сохраняется для анализа возможного повторного использования, но шесть отсутствующих в договоре отчётов не входят в обязательный scope.

Статус названий, блоков и назначений: `CONFIRMED`. Возможные домены повторного использования основаны только на описаниях и имеют статус `ASSUMPTION`; подтвердить их можно лишь SQL/M/DAX и source mapping.

На 2026-08-03 по всем 31 договорным отчётам завершены локальные бизнес-анализ,
source-to-target mapping, проектная архитектура и Power BI data contract.
Физическая реализация и техническая server validation отложены. Общие домены
посещений, ДПФУ, ИП, CRM, предзаписи/расписания и поступлений выделены только
при доказанном совпадении grain и семантики; отчётные копии сырых регистров не
проектируются. Внешние Excel/Google Sheets источники, для которых пользователь
подтвердил текущую границу, остаются в Power BI.

## Предварительные кандидаты на повторное использование

| Статус | Кандидат | Отчёты |
|---|---|---|
| CONFIRMED REUSE / different grains preserved | события посещений | client-day, hourly, checkpoint и debt movements используют общие source rules, но остаются отдельными продуктами по ADR-0003/0013/0021/0022 |
| CONFIRMED REUSE / different temporal semantics | абонементы и сроки действия | newcomer, preparation, renewal, Renew и client base не объединяются скрыто |
| CONFIRMED REUSE | выручка ДПФУ/услуг | единый `mart.ancillary_revenue_movement` с report views; KPI/ДПФУ/рецепция/записи/загрузка |
| CONFIRMED REUSE / group summary has different grain | членство и поступления | «Отчет по поступлениям» и «Отчет членство для правления» используют один detailed membership domain и одинаковые KPI; «Свод выручка ГК» использует те же source branches, но дневной aggregate другой гранулярности; «Пульс клуба» вне договорного scope |
| CONFIRMED REUSE / task vs interaction separated | лиды, задания и конверсии | task-факт фитнес/маркетинговой воронки отделён от CRM interaction core и client-event фитнес-воронки |
| CONFIRMED REUSE / different grains preserved | уроки, записи и расписание | общий group lesson, отдельные state events, 5-minute slots, employee intervals и IP training |

## Отложенные технические параметры

Физические типы и ключи 1С, source states, реальные кардинальности, объёмы,
контрольные значения, планы выполнения и фактический SLA имеют статус
`VALIDATION_PENDING`. Их проверка не меняет подтверждённые бизнес-правила без
отдельного обнаруженного расхождения.
