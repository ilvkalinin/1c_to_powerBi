# Query review: «Фитнес воронка»

Статус: `BUSINESS REVIEW COMPLETE / TECHNICAL VALIDATION PARTIALLY VALIDATED (SV-079)`.
Основание — полный доступный M/SQL/DAX из `Фитнесворонка.docx`,
бизнес-описание `Фитнес воронка.docx` и PBIT `Фитнес воронка.pbit`, полученный
2026-07-31. Запросы к БД не выполнялись; все шаблоны ниже имеют статус
`NOT_EXECUTED — ожидается подключение к корпоративной сети`.

## Разбор текущих запросов

### `Спр Абонементы`

Источник — `Reference59`, с клиентом `Reference141X1` и клубом доступа
`Reference132`. SQL применяет временную нижнюю границу `2024-01-01`, исключает
некорректный интервал, будущие начала, ИП, сотрудников, clip-карты и пустой
код клиента. Power Query дополнительно оставляет срок свыше шести, известный
стаж, ненулевого клиента и возраст от 14 на дату активации.

`Table.Distinct(ДатаНачала, КодКлиента)` не задаёт правило выбора ссылки
контракта. Это риск R-01: один и тот же клиент может потерять контракт или
получить недетерминированную ссылку до расчёта всех последующих мер.

### `ПосещенияСПТ`

`InfoRg7006` соединяется с `Document329`, сотрудником, клиентом, статусом
`Enum448.Order = 4`, услугой дочерней заданному родителю купонов и клубом.
Затем визит из `Document325` принимается только у того же клиента, в том же
клубе и на календарный день занятия. `DISTINCT ON(client)` назначает событию
последний по дате окончания клубный контракт клиента, без условия, что
контракт действовал на день занятия.

По решению пользователя от 2026-07-30 assignment к контракту не переносится
в целевую логику: СПТ принадлежит клиенту cohort, а дата СПТ сохраняется.
Тем самым R-02 устранён. R-03 остаётся технической проверкой: сравнение клуба
по текстовому названию должно быть заменено доказанным ID-сопоставлением.

### `ПосещенияДПФУ`, `ПЗ ИП`, `ГЗ ИП`

ДПФУ объединяет агрегированные движения `AccumRg7575` и `AccumRg7646` с
двумя наборами ИП из `InfoRg7006` и документов. Текущий запрос назначает
движению один из действующих договоров клиента, но это больше не требуется:
по решению пользователя от 2026-07-30 результат принадлежит клиенту cohort.
Фильтры набора — набор GUID,
виды деятельности, исключение посещения клуба, ненулевые поступления и
исключение купонов.

R-04, связанный с `ROW_NUMBER` contract assignment, устранён из target rule.
R-05: `Table.Combine`
смешивает движения ДПФУ и ИП; единица `COUNTROWS` в DAX может означать разные
типы событий. R-06: текущий SQL изменяет `work_mem`; это не должно быть частью
будущего продукта без измерений и согласования.

### «Физкульт Гайд» и отмены

Основной набор требует запись на точную специальную услугу, фактический визит
того же клиента в том же клубе и в день занятия. В M применяется anti-join с
набором отмен по `(client_code, booking_id)`. В запросе отмен предварительная
ветка одновременно соединяет `Document329` и `Document283` по одному ID;
совместимость типов документов не доказана.

R-07: ключ отмены и корректность обеих веток требуют проверки; нельзя
считать anti-join подтверждённым бизнес-правилом вне текущего отчёта.

### DAX

Карточки 1/2/12 месяцев определяют когорту по месяцу начала. Решением
пользователя все этапы измеряются как distinct клиенты, а не contract rows.
Разные окна DAX не конфликтуют: периодные меры измеряют результат в выбранном
окне, а detail и справочные карточки — актуальный результат для работы с
клиентом после старта. Поэтому будущий outcome-набор хранит дату события, а
не один статический флаг на cohort-строке.

`SELECTEDVALUE` для сотрудника СПТ/ДПФУ возвращает `BLANK`, если на контракте
несколько сотрудников. В detail это не эквивалентно «сотрудник отсутствует».

## Read-only SQL-шаблоны второго этапа

```sql
-- V-02: несколько eligible-контрактов одного клиента в дату старта.
WITH eligible_contracts AS (
    SELECT c._IDRRef AS contract_id,
           c._Fld681RRef AS client_id,
           c._Fld671::date AS start_date
    FROM <source_schema>._Reference59 c
    INNER JOIN <source_schema>._Reference141X1 cl
      ON cl._IDRRef = c._Fld681RRef
    WHERE c._Fld671 < c._Fld672
      AND c._Fld671 < CURRENT_DATE
      AND cl._Code IS NOT NULL
      AND c._Fld693 > 6
)
SELECT client_id, start_date, COUNT(*) AS contract_count
FROM eligible_contracts
GROUP BY client_id, start_date
HAVING COUNT(*) > 1;

```
