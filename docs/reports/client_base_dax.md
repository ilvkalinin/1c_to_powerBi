## Выбор клубного или сетевого итога

В фактах хранятся два взаимоисключающих уровня:

- `Клуб` — уникальный клиент внутри клуба;
- `Сеть` — уникальный клиент по сети.

Если в контексте есть клуб, мера читает строки `Клуб`. Без фильтра/строки клуба мера читает строки `Сеть`. Поэтому итог матрицы по клубам будет уникальным сетевым итогом, а не суммой строк клубов.

Создать скрытую служебную меру:

```DAX
__Уровень охвата =
VAR ЕстьКлуб =
    ISINSCOPE ( 'Клубы'[Клуб] )
        || ISCROSSFILTERED ( 'Клубы'[Код клуба] )
RETURN
    IF ( ЕстьКлуб, "Клуб", "Сеть" )
```

Значения `Клуб` и `Сеть` — русские значения, которые Power Query получает преобразованием физических `club` и `network`.

## Основные меры

```DAX
Клиентская база =
VAR Уровень = [__Уровень охвата]
RETURN
    IF (
        NOT HASONEVALUE ( 'Отчетные даты'[Отчетная дата] ),
        BLANK (),
        SWITCH (
            Уровень,
            "Клуб",
                CALCULATE (
                    SUM ( 'Клиентская база'[Количество клиентов] ),
                    KEEPFILTERS ( 'Клиентская база'[Уровень охвата] = "Клуб" )
                ),
            "Сеть",
                CALCULATE (
                    SUM ( 'Клиентская база'[Количество клиентов] ),
                    REMOVEFILTERS ( 'Клубы' ),
                    KEEPFILTERS ( 'Клиентская база'[Уровень охвата] = "Сеть" )
                )
        )
    )
```

```DAX
Клиентская база на начало года =
VAR ДатаСравнения =
    SELECTEDVALUE ( 'Отчетные даты'[Дата начала года] )
RETURN
    IF (
        NOT ISBLANK ( ДатаСравнения ),
        CALCULATE (
            [Клиентская база],
            REMOVEFILTERS ( 'Отчетные даты' ),
            TREATAS ( { ДатаСравнения }, 'Отчетные даты'[Отчетная дата] )
        )
    )
```

```DAX
Прирост к началу года, шт. =
[Клиентская база] - [Клиентская база на начало года]
```

```DAX
Прирост к началу года, % =
DIVIDE (
    [Прирост к началу года, шт.],
    [Клиентская база на начало года]
)
```

```DAX
Клиентская база год назад =
VAR ДатаСравнения =
    SELECTEDVALUE ( 'Отчетные даты'[Сравнимая дата прошлого года] )
RETURN
    IF (
        NOT ISBLANK ( ДатаСравнения ),
        CALCULATE (
            [Клиентская база],
            REMOVEFILTERS ( 'Отчетные даты' ),
            TREATAS ( { ДатаСравнения }, 'Отчетные даты'[Отчетная дата] )
        )
    )
```

```DAX
Прирост к прошлому году, шт. =
[Клиентская база] - [Клиентская база год назад]
```

```DAX
Прирост к прошлому году, % =
DIVIDE (
    [Прирост к прошлому году, шт.],
    [Клиентская база год назад]
)
```

Процентные меры форматируются как `0,0%;-0,0%;–`. Количества — как целые числа. При нулевой или отсутствующей базе сравнения `DIVIDE` возвращает `BLANK`.

## Активность

```DAX
Активная клиентская база =
CALCULATE (
    [Клиентская база],
    REMOVEFILTERS ( 'Активность' ),
    'Активность'[Категория активности] <> "Не ходил"
)
```

```DAX
Активная клиентская база, % =
VAR ВсяБаза =
    CALCULATE (
        [Клиентская база],
        REMOVEFILTERS ( 'Активность' )
    )
RETURN
    DIVIDE ( [Активная клиентская база], ВсяБаза )
```

```DAX
Доля категории активности, % =
VAR ВсяБаза =
    CALCULATE (
        [Клиентская база],
        REMOVEFILTERS ( 'Активность' )
    )
RETURN
    DIVIDE ( [Клиентская база], ВсяБаза )
```

`Активная клиентская база, %` намеренно игнорирует выбранную категорию активности: это доля всех клиентов, у которых было хотя бы одно посещение за окно `[дата - 30 дней, дата)`.

```DAX
Прирост к плану, шт. =

```

Файл Excel должен содержать не более одной строки на ключ `Отчетная дата × Уровень охвата × Код клуба`. Для уровня `Сеть` код клуба пустой. Если сетевого плана нет, сетевые меры плана возвращают `BLANK`.

## Защитные правила модели

- На странице должна быть выбрана ровно одна отчётная дата; при множественном выборе основные меры возвращают `BLANK`.
- Нельзя создавать неявные суммы по числовым колонкам фактов; у них свойство `Суммировать по умолчанию` устанавливается в `Не суммировать`.
- Нельзя одновременно складывать уровни `Клуб` и `Сеть`.
- Нельзя вычислять удержание как текущую базу, делённую на прошлую базу: это разные множества клиентов.
- Снимки не суммируются по датам.
- Проценты и темпы роста не суммируются.
- Тяжёлые объединения, distinct клиентов, интервальная логика, возраст, стаж и 30-дневная активность остаются в PostgreSQL.

## Оставшиеся зависимости

- `VALIDATION_PENDING — implementation blocker`: подтвердить статусы объектов 1С; неизвестные возраст, пол и стаж
  выводятся как `Не указано` по решению пользователя 2026-07-30.
- `VALIDATION_PENDING — implementation blocker`: получить metadata типов и ключей источника.
- `BLOCKER для сверки`: получить минимум два контрольных среза.
- `CONFIRMED`: план по сети вычисляется как сумма клубных строк; Excel-план
  приводится к ключу и русским колонкам при его подключении.
