# S3-RGS-LOAD-001: первичная загрузка «Свода выручка ГК»

Дата согласования: 2026-08-20. Статус: `COMPLETED / VALIDATED`.

Пользователь явно одобрил полный пакет первичной загрузки после предложения
«Свод выручка ГК — первичная загрузка». Предыдущее явное указание пользователя
разрешает не показывать точный SQL, если он воспроизводит уже согласованные
таблицы, схемы, mapping и правила.

## Граница пакета

- атомарно заполнить существующую
  `mart.revenue_group_summary_daily` только внутренними статьями `02`–`06`;
- применить BR-003 и подтверждённый grain
  `дата × клуб × статья`;
- взять `03` из `mart.ancillary_revenue_movement` и `04` из
  `mart.ip_revenue_daily` с исключением пустого клуба;
- сформировать только временные source-side ветви для `02`, `05` и `06`,
  затем выполнить итоговую агрегацию;
- выполнить branch-, ключевые, суммовые, date-boundary и rerun-сверки,
  замерить длительность полного refresh и зафиксировать SLA-результат.

## Исключения

В пакет не входят Excel-статьи `07`–`13`, планы и бюджеты, изменение Power BI,
создание либо загрузка отдельного рецепционного детального факта, DDL и любое
изменение read-only источника 1С.

## Операции и rollback

Разрешён DML только в существующей `mart.revenue_group_summary_daily`:
атомарная замена данных одного BR-003 горизонта после прохождения source-side
контролей. До commit rollback — `ROLLBACK`; при ошибке исходные строки
сохраняются. DDL не выполняется.

## Критерий закрытия

Факт совпадает с независимо сформированным контрольным source-side набором по
ветвям, ключу, строкам и суммам; повторный прогон стабилен; задокументирована
фактическая длительность refresh. Внешняя модель Power BI не меняется.

20.08.2026 первая попытка сверки была откачена без DML: она неправомерно сопоставила
живой source snapshot с ранее загруженным содержимым двух reused facts. После
уточнения пользователя этот результат не считается `BLOCKER`. Продолжение
пакета сначала сравнивает оба source extract в одном `REPEATABLE READ`
снимке 1С; только затем допускается загрузка.

Последующая source-to-source сверка в одном `REPEATABLE READ` снимке подтвердила
reuse статьи `03`, но обнаружила действительное расхождение статьи `04`:
existing shared extract использовал `ILIKE '%ИП%'` и включал «Клип карта»;
current M использует `LIKE '%ИП%'` и эти строки исключает. Пользователь выбрал
remediation shared fact (S3-IP-REMEDIATION-001); после его exact-M rebuild
reuse `03`/`04` согласован и initial load выполнен.
