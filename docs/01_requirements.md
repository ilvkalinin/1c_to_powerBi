# Требования

Этот файл хранит общие требования. Требования отдельных отчётов создаются из `docs/reports/_template.md`.

## Общие требования

| Статус | Требование | Источник |
|---|---|---|
| CONFIRMED | Power BI получает подготовленные данные со стабильными типами и структурой | исходное ТЗ |
| CONFIRMED | Каждая колонка прослеживается до источника | исходное ТЗ |
| CONFIRMED | Фактовые строки имеют одну известную гранулярность | исходное ТЗ |
| CONFIRMED | Тяжёлые объединения, группировки и повторяемые вычисления не остаются над сырыми данными в Power Query | исходное ТЗ |
| CONFIRMED | База витрин не содержит полной копии сырых регистров | сообщение пользователя 2026-07-23 |
| CONFIRMED | Сетевой обмен ограничивается необходимыми данными рабочего периода | сообщение пользователя 2026-07-23 |
| CONFIRMED | Разработка начинается с уже существующих отчётов и их эталонной логики | сообщение пользователя 2026-07-23 |

## Принцип повторного использования

Разрабатывать итеративно по одному существующему отчёту. Это не означает обязательную отдельную физическую таблицу на каждый отчёт:

- если новый отчёт имеет ту же гранулярность, показатели и правила, использовать существующую витрину;
- если повторяется только справочник или стабильная бизнес-логика, выделить общий объект после подтверждения реального повторного использования;
- если гранулярность или смысл показателей различаются, создать отдельную витрину и не смешивать уровни детализации;
- не создавать заранее универсальный `core` и не дублировать одинаковые расчёты в нескольких витринах.

## Gate нового отчёта

До mapping должны быть известны или явно помечены: бизнес-задача, пользователи, решения, показатели, разрезы, фильтры, гранулярность, период истории, обновление/SLA, источники, правила и контрольные значения. Для существующего отчёта дополнительно нужны исходный SQL, полный M-код Power Query, используемые DAX-меры и схема связей Power BI.
